# AXE Genesis — Q-Executor Multi-Horizon Label Bug: Investigation & Fix

## Status: CONFIRMED — Phase 1b mislabels all 3 oracle actions using cross-horizon fwd_pct

---

## 1. Root Cause (what the code actually does)

### Phase 1b in `evaluate_option_expiries.py` (lines 558–622)

```python
# Line 567–569
max_fwd_cp = max([float(train_df.iloc[idx + k][close_col]) for k in (1, 3, 6, 12)])
min_fwd_cp = min([float(train_df.iloc[idx + k][close_col]) for k in (1, 3, 6, 12)])
fwd_pct = (max_fwd_cp - cp) / ... if abs(max_fwd_cp - cp) > abs(min_fwd_cp - cp) else ...
```

`fwd_pct` is the **best possible move across all 4 horizons combined** — it picks whichever is larger in absolute terms (the 1-bar, 3-bar, 6-bar, or 12-bar close). This is used for:

1. **Quality gating** (skip if `abs(fwd_pct) < min_fwd`) — fine on its own
2. **Oracle label** (CALL/PUT/WAIT at lines 601–606) — **wrong**: the oracle fires on the *aggregate best* not the horizon the meta said to use
3. **Reward** (line 608–611) — **wrong**: `pnl_pct=fwd_pct` is the best across all horizons, not the horizon the Q-executor would actually hold to

### What makes it a *label* bug (not just a reward bug)

The 28-dim state vector (lines 6–9 of `build_state_vector`) already contains:
- `horizon_strengths[4]` — the meta's per-horizon conviction  
- `optimal_horizon_idx` — the meta's recommended expiry index  
- `recommended_expiry` — human-readable label ("5m", "15m", "30m", "1h")

The oracle **ignores all of this**. A bar where the meta says "this is a 1h setup, `optimal_horizon_idx=3`" gets labelled CALL if `max(close+1, close+3, close+6, close+12)` moves up 0.15% — which might be close+1 (5m). The Q-net sees the 1h-heavy state vector, gets told BUY_CALL, then at eval time it's scored against the 5m outcome. Every horizon is systematically cross-contaminated.

### Phase 2 early-stop evaluation adds a third mismatch (line 684)

```python
v_exp_row = train_df.iloc[v_idx + 3]  # hardcoded +3 bars (15m)
```
Win-rate checkpoint picks the best model based on 15m outcome, regardless of what horizon the meta recommended. Best Q weights are selected by the wrong criterion.

### Phase 3 test evaluation (lines 751–800) is correct

Phase 3 loops over each horizon separately and scores each action against that horizon's actual expiry row. This is the only place that is horizon-aware. The trained Q-net that arrives here has been trained with wrong labels — Phase 3 shows the damage.

## 2. The Exact Fix for Phase 1b in `evaluate_option_expiries.py`

Replace lines **558–622** (the inner `for idx` loop body within Phase 1b) with the following:

```python
HORIZON_BARS_LIST  = [1, 3, 6, 12]          # 5m, 15m, 30m, 1h
HORIZON_LABELS_LIST = ["5m", "15m", "30m", "1h"]

for idx in range(len(train_df) - 13):
    if q_buf_filled >= Q_BUFFER_TARGET:
        break
    q_buf_attempts += 1

    row = train_df.iloc[idx]
    cp  = float(row[close_col])

    # ── Zone update (unchanged) ──
    if idx == 0 or idx % 15 == 0 or len(zone_manager_gen.get_active_zones()) == 0:
        update_real_snr_snapshot(train_df, idx, zone_manager_gen)
    zone_manager_gen.update_invalidation(cp, float(row[high_col]), float(row[low_col]))

    # ── Meta prediction ──
    f_dict = _row_to_feature_dict(row, close_col, vol_col)
    pred   = meta_learner.predict(f_dict)
    ms     = float(pred.get("signal_strength", 0.5))
    h_strengths = pred.get("horizon_strengths", [0.5, 0.5, 0.5, 0.5])

    # ── Resolve which horizon to use for THIS transition ──
    opt_idx  = int(pred.get("optimal_horizon_idx", 2))
    if not (0 <= opt_idx < 4):
        opt_idx = int(np.argmax(h_strengths)) if h_strengths else 2
    lookahead   = HORIZON_BARS_LIST[opt_idx]
    rec_expiry  = HORIZON_LABELS_LIST[opt_idx]

    if idx + lookahead >= len(train_df):
        continue

    # ── Forward move evaluated at the *recommended* horizon (not the aggregate max) ──
    expiry_close = float(train_df.iloc[idx + lookahead][close_col])
    fwd_pct      = (expiry_close - cp) / (cp + 1e-8)

    # Quality gate: still use horizon-specific move
    if ms < min_ms and abs(fwd_pct) < min_fwd:
        continue

    bias = HTFBiasPackage(
        direction="bullish" if ms > 0.5 else "bearish",
        strength=ms,
        reversal_prob=float(pred.get("reversal_prob", 0.2)),
        q_value=float(pred.get("q_value", 0.5)),
        expected_mfe_pips=float(pred.get("expected_mfe_pips", 50.0)),
        expected_mae_pips=float(pred.get("expected_mae_pips", 15.0)),
        horizon_strengths=h_strengths,
        optimal_horizon_idx=opt_idx,
        recommended_expiry=rec_expiry,
    )
    ctx          = _make_exec_ctx(symbol, cp, dict(row))
    state        = q_executor.build_state_vector(bias, account, ctx, zone_manager_gen)
    mask_engine  = HardActionMask()
    action_mask  = mask_engine.get_action_mask(
        current_price=cp, atr=ctx.atr, zone_manager=zone_manager_gen,
        buy_volume=ctx.buy_volume, sell_volume=ctx.sell_volume, has_open_position=False,
    )

    # ── Oracle: horizon-aware label ──
    MOVE_THRESH = 0.0015
    if action_mask[1] == 1 and bias.direction == "bullish" and fwd_pct >= MOVE_THRESH:
        oracle_action = 1   # BUY_CALL — price did move up at the recommended horizon
    elif action_mask[2] == 1 and bias.direction == "bearish" and fwd_pct <= -MOVE_THRESH:
        oracle_action = 2   # BUY_PUT
    else:
        oracle_action = 0   # WAIT

    # ── Reward: matched to the same horizon ──
    reward = q_executor.calculate_executor_reward(
        action=oracle_action, action_mask=action_mask, pnl_pct=fwd_pct,
        max_drawdown_exposed=0.005, forward_move_pct=fwd_pct, htf_bias=bias,
    )

    next_row   = train_df.iloc[idx + 1]
    next_cp    = float(next_row[close_col])
    next_ctx   = _make_exec_ctx(symbol, next_cp, dict(next_row))
    next_state = q_executor.build_state_vector(bias, account, next_ctx, zone_manager_gen)

    q_executor.record_transition(state, oracle_action, reward, next_state, False, action_mask)
    q_buf_filled += 1

    if q_buf_filled % 2000 == 0:
        print(f"  [Phase 1b] Buffer: {q_buf_filled}/{Q_BUFFER_TARGET} | Scanned: {q_buf_attempts} bars")
```

## 3. Optional Stronger Version: Multi-Horizon Buffer

Instead of one transition per bar (for the single recommended horizon), emit one transition **per strong horizon** — this gives the Q-net more signal and lets it learn which horizon is context-appropriate from `horizon_strengths[4]` in the state:

```python
for h_idx, (h_bars, h_label) in enumerate(zip(HORIZON_BARS_LIST, HORIZON_LABELS_LIST)):
    if idx + h_bars >= len(train_df):
        continue
    h_strength = float(h_strengths[h_idx]) if h_idx < len(h_strengths) else 0.5
    if h_strength < 0.52:          # skip weak horizons
        continue
    if q_buf_filled >= Q_BUFFER_TARGET:
        break

    expiry_close_h = float(train_df.iloc[idx + h_bars][close_col])
    fwd_pct_h      = (expiry_close_h - cp) / (cp + 1e-8)

    bias_h = HTFBiasPackage(
        direction="bullish" if ms > 0.5 else "bearish",
        strength=h_strength, reversal_prob=float(pred.get("reversal_prob", 0.2)),
        q_value=float(pred.get("q_value", 0.5)),
        expected_mfe_pips=float(pred.get("expected_mfe_pips", 50.0)),
        expected_mae_pips=float(pred.get("expected_mae_pips", 15.0)),
        horizon_strengths=h_strengths,
        optimal_horizon_idx=h_idx,
        recommended_expiry=h_label,
    )
    # ... same mask + oracle + reward + record_transition logic ...
    q_executor.record_transition(state_h, oracle_h, reward_h, next_state_h, False, action_mask_h)
    q_buf_filled += 1
```

This produces up to 4× more transitions per bar, reaching Q_BUFFER_TARGET faster. The Q-net state already includes `horizon_strengths[4]` so it can differentiate "act on 5m conviction" from "act on 1h conviction" from the same bar — which is the whole point.

## 5. Same Bug in `prepare_kaggle_bundle.py` (Phase 2, lines 958–961)

```python
# prepare_kaggle_bundle.py lines 958-961 (CELL_PHASE2_Q_TRAINING):
fwd_cps = [float(train_df.iloc[idx + lookback_bars + k][close_col]) for k in (1, 3, 6, 12) if ...]
max_cp, min_cp = max(fwd_cps), min(fwd_cps)
fwd_pct = (max_cp - cp) / ... if ... else ...
```

Same aggregate-max collapsing bug. Fix identically: resolve `opt_idx` from `bias.optimal_horizon_idx`, look up `lookahead = HORIZON_BARS_LIST[opt_idx]`, and use `close_prices[abs_idx + lookahead]` as the sole `fwd_pct`.

The `CELL_PHASE2_Q_TRAINING` constant string in `prepare_kaggle_bundle.py` generates the Kaggle notebook Phase 2 cell — the fix must go into the string template there, not just in the local `evaluate_option_expiries.py`.
