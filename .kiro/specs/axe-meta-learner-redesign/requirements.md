# Requirements: AXE Meta-Learner Redesign & Notebook-App Parity

## Introduction

The current AXE Genesis training pipeline (`notebooks/training/axe_meta_q_learner_sync.ipynb`) has two active bugs blocking training progress, and the broader architecture needs redesigning to take advantage of the rich target labels already produced by `ml_dataset_preparation.py`. Additionally, the notebook and the in-house backend code (`app/core/ml/`) have diverged and need to be reconciled cell by cell to ensure 1:1 parity.

The central question the system must answer is: **"Given a market context, what is the best option expiry horizon for this trade — 5m, 15m, 30m, or 1h?"**

## Bug Analysis

### Bug 1 — Zero Forward-Move Targets (Phase 1 training produces no signal)

**Current behavior**: The Phase 1 training diagnostic prints:
```
strength mean/std per H: [0.5 0.5 0.5 0.5] [0. 0. 0. 0.]
pips mean/std: [0. 0. 0. 0.] [0. 0. 0. 0.]
```
All strength targets are exactly 0.5 and pips targets are exactly 0.0. The `_extract_targets()` function in Cell 7 computes `fwd[h_key] / (atr_vals_local * sqrt(h_bars))` but the numerator `forward_move_*` is all zeros, so all computed targets collapse to the clipped midpoint 0.5.

**Root cause**: The guard `if "forward_move_1" not in df.columns` only synthesizes the columns if absent. In the loaded CSV the columns ARE present but contain zeros because the CSV was generated by `evaluate_option_expiries.py` which computes them after calling `align_multi_timeframe_datasets()`. When the dataset was last regenerated, the `data/` folder had been cleaned and only synthetic/zero data was available from the Alpaca API timeout fallback.

**Impact**: The `strength_head`, `pips_head`, `risk_head`, and `liquidity_head` all receive constant targets and their losses immediately collapse to near-zero (visible in training log: `Str=4.1e-05` → `4.0e-07` by step 200 of epoch 1). Only `reversal_head` (`Rev=0.21`) survives because it uses `dirs[1] != dirs[3]` which does produce non-trivial targets from the direction columns. The `q_head` also trains because `target_dir_*` columns have a non-trivial mean (~0.50–0.54).

**Required fix**: Force recomputation of `forward_move_*` regardless of whether columns exist in the CSV. Remove the `if "forward_move_1" not in df.columns` guard so targets are always freshly computed from the actual close prices in the loaded dataframe.

### Bug 2 — Q_LOOKBACK NameError in Phase 2 (Cell 8 crash)

**Current behavior**: Cell 8 crashes immediately with `NameError: name 'Q_LOOKBACK' is not defined` at the `ExecutorQNetwork(...)` instantiation line. The traceback shows `execution_count=1` on Cell 8, while Cell 7 is `execution_count=7` — indicating the kernel was reset between runs and Cell 6 (which defines `Q_LOOKBACK = 64`) was not re-executed.

**Root cause**: Kaggle notebook cells can be run out of order after a session restart. `Q_LOOKBACK` is defined as a module-level constant in Cell 6 but is referenced in Cell 8 without defensive fallback.

**Required fix**: Add `Q_LOOKBACK = Q_LOOKBACK if 'Q_LOOKBACK' in dir() else 64` guard at the top of Cell 8, or better: move `Q_LOOKBACK` definition to Cell 1 (the constants/imports cell) so it always exists regardless of execution order.

## Architecture Redesign Requirements

### Meta-Learner (SignalMetaNetwork)

#### Context window design
The meta-learner uses a **dual-window approach**:
- **1k-bar context tower** (Branch 1): The full 1000-bar sequence passes through the Conv1D+LSTM tower. This gives the model a long view of how price has interacted with zones and what the broader regime has been. This is primarily a context/memory encoder.
- **150-bar prompt** (Branches 2 and 3 + all prediction heads): Each prediction head receives only the last 150 bars as its direct input. The 150 bars are the "prompt" — recent enough to reflect current conditions, short enough for the heads to specialize.

**Rationale**: The 1k context teaches the model that "this zone held 3 times over 800 bars" while the 150-bar prompt asks "given what's happening right now, which horizon has edge?"

#### Per-head isolation requirement
The current architecture has a single `branch_cat = cat([b1_out, b2_out, b3_out])` that feeds all auxiliary heads. While `detach()` prevents gradient flow FROM the aux heads TO the branch encoders, it does NOT prevent different aux heads from sharing the same feature representation. This causes **head contamination** — the reversal head and the direction head are trained from the same feature vector, so the gradients from a strong reversal loss can dominate the shared representation.

**Required change**: Each prediction head group must have its own mini-encoder that operates on the 150-bar prompt independently:
- `direction_encoder`: Conv1D(num_features → 32) → Pool → FC(32, 32)
- `zone_encoder`: Conv1D(num_features → 32) → Pool → FC(32, 32)
- `reversal_encoder`: Conv1D(num_features → 32) → Pool → FC(32, 32)
- `strength_encoder`: Conv1D(num_features → 32) → Pool → FC(32, 32)

Each encoder processes the same 150-bar window independently. The heads are trained with isolated optimizers (or at minimum, stopgradient isolation), so the direction head's gradient cannot contaminate the zone head's encoder weights.

**Note**: "Learn them by list" means the model processes target groups sequentially/independently, not through a shared embedding. The model must learn to be "aware" that these are different prediction tasks.

#### Output contract (HTFBiasPackage)
The meta-learner must output a complete `HTFBiasPackage` containing:
- `direction`: "bullish" | "bearish" | "neutral"
- `strength`: float [0,1] — overall conviction
- `horizon_strengths`: [float × 4] — per-horizon edge (5m, 15m, 30m, 1h)
- `optimal_horizon_idx`: int — argmax of horizon_strengths
- `recommended_expiry`: str — "5m" | "15m" | "30m" | "1h"
- `reversal_prob`: float [0,1]
- `expected_mfe_pips`: float — ATR-normalised expected favorable move
- `expected_mae_pips`: float — ATR-normalised expected adverse move

#### Target heads (exhaustive list)
1. **q_head** → 4-dim softmax: direction [DOWN, WAIT, UP, NEUTRAL] per horizon
2. **strength_head** → 4-dim sigmoid: horizon-specific edge strength [0,1]
3. **selector_head** → 4-dim CrossEntropy: which horizon is optimal (primary training signal)
4. **pips_head** → 4-dim regression: ATR-normalised forward move per horizon
5. **risk_head** → 8-dim regression: [MFE_h1, MAE_h1, MFE_h2, MAE_h2, MFE_h3, MAE_h3, MFE_h4, MAE_h4]
6. **reversal_head** → 1-dim sigmoid: reversal_prob
7. **bull_conf_head** → 1-dim sigmoid: is this a BULL bar?
8. **bear_conf_head** → 1-dim sigmoid: is this a BEAR bar?
9. **next_zone_head** → 7-dim softmax: which zone (r1/r2/r3/s1/s2/s3/none) did price reach next
10. **liquidity_head** → 2-dim regression: [|move_5m|/ATR, |move_15m|/ATR]

### Q-Executor (ExecutorQNetwork)

#### Context window
- `Q_LOOKBACK = 150` to 300 bars (upgraded from 64) — enough to see zone interactions
- The Q-learner receives: `feat_window (B, 150, num_features)` + `ctx (B, ctx_dim)` where `ctx_dim` includes the full `HTFBiasPackage` output from the meta-learner

#### Replay buffer design
Two separate replay buffer tracks:

**Track A — Main experience buffer** (existing):
- `(feat_window, ctx_state, action, reward, next_feat_window, next_ctx_state, mask)`
- Standard Q-learning transitions

**Track B — Regret/opportunity buffer** (new):
- Records transitions where: action=WAIT was chosen, but at least one horizon h would have been profitable (|fwd_pct_h| >= 0.0015 and direction was correct)
- Tuple: `(feat_window, ctx_state, H_WAIT, regret_reward, next_feat_window, next_ctx_state, mask, optimal_horizon_idx, counterfactual_pct)`
- `regret_reward = -abs(fwd_pct_optimal_horizon)` — missed profit penalty
- The Q-learner samples from Track B at ~20% rate during training

**Purpose**: The Q-learner must learn "I should not WAIT when there is a high-confidence signal at a zone AND the forward move at some horizon would have been profitable." The regret buffer provides direct counterfactual supervision.

**Implementation**: Use a `collections.deque(maxlen=10000)` for Track B. Sample from it at 20% rate in the batch update loop (`if random.random() < 0.20: batch = random.sample(regret_buffer, min(batch_size//5, len(regret_buffer)))`).

#### Per-horizon separation (unchanged)
- 4 independent heads, each producing [WAIT, CALL, PUT]
- Separate replay buffer per horizon (already in current code)
- Each head only receives its own horizon's reward
